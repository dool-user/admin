# 経理チーム 共通ルール

経理チーム（`.claude/agents/keiri-*.md`）の全員が、作業前に必ず読むルールです。

## 1. 会社の前提

| 項目 | 内容 | 状態 |
|---|---|---|
| 会社 | グラハムコミュニケーションズ株式会社（法人） | 確定 |
| 会計ソフト | freee会計 | 確定 |
| 事業 | でんき開通サポート（引越し時の電気・ガス・水道・ネット開通手続きの取次・代行）、業務委託案件の管理 | 確定 |
| 決算月 | **★未設定**（例：3月決算） | 要記入 |
| 消費税 | **★未設定**（原則課税／簡易課税、課税事業者かどうか、インボイス登録番号） | 要記入 |
| 経理方式 | 税込経理（freee の標準）を前提。税抜経理の場合はここを書き換える | 要確認 |
| 税理士 | **★未設定**（顧問税理士の有無・連絡方法） | 要記入 |

★の項目が未設定のまま結論に影響する場合は、推測で埋めずに「前提：〇〇と仮定」と明記してユーザーに確認すること。

## 2. 絶対に守ること

1. **freee への書き込みは、ユーザーが内容を確認して「登録してよい」と言ってから。** freee-mcp の `freee_api_post / put / patch / delete` は実データを直接変更する。エージェントは下書き（CSV・表）を作るところまで。
2. **推測で数字を作らない。** 金額・日付・取引先は元資料（明細・請求書・領収書）にあるものだけを使う。読めない・足りないものは「要確認」として一覧にする。
3. **生データをコミットしない。** 通帳・カード明細・請求書PDF・給与データなどは `accounting/inbox/` に置く（Git 管理外）。成果物は `accounting/output/`（Git 管理外）に出す。
4. **税務判断は根拠つきで。** 判断に迷うもの・金額が大きいもの（目安：1件10万円以上）・例外処理は「要税理士確認」とし、理由と論点を書く。
5. **制度は変わる。** 税率・経過措置・特例は `accounting/rules/tax-notes.md` を確認し、書かれていない・古い（最終確認日から1年超）場合は国税庁などの一次情報を調べ直す。

## 3. 作業の流れ（全員共通）

```
元資料（inbox/）→ 下書き作成（各担当）→ 税務レビュー（keiri-zeimu-review）→ ユーザー確認 → freee へ登録
```

## 4. 出力の書き方

- ファイル名：`accounting/output/YYYY-MM_内容.拡張子`（例：`2026-09_仕訳下書き.csv`）
- 金額は円・整数、カンマなし（CSV の場合）。日付は `YYYY-MM-DD`。
- 各成果物の最後に「要確認リスト」（何が・なぜ・誰に確認するか）を付ける。要確認がなければ「なし」と書く。
- 事実（資料にある）／判断（ルールに基づく）／推測（仮定）を区別して書く。
