# 経理チーム（AIエージェント）

freee会計を使う前提の、Claude Code のサブエージェントによる経理チームです。明細・請求書から**下書き（仕訳・請求書・支払予定表・月次レポート）を作るところまで**を担当し、freee への登録や振込はユーザーが確認してから行います。

## メンバー

| 担当 | エージェント | 主な仕事 |
|---|---|---|
| 窓口・まとめ役 | `/keiri`（スキル） | 依頼の振り分け、月次締めの進行、報告 |
| 仕訳・記帳 | `keiri-shiwake` | 明細・領収書 → 勘定科目・税区分 → 仕訳の下書き |
| 請求・売掛金 | `keiri-seikyu` | 請求書（適格請求書）作成、入金消込、未入金の管理 |
| 支払・経費 | `keiri-shiharai` | 受領書類のインボイス要件チェック、源泉徴収、支払予定表 |
| 月次決算・レポート | `keiri-kessan` | 月次締めチェック、試算表レビュー、月次レポート（広告の費用対効果を含む） |
| 税務チェック | `keiri-zeimu-review` | 成果物のレビュー（読み取り専用。ファイルは書き換えない） |

定義ファイルは `.claude/agents/keiri-*.md` と `.claude/skills/keiri/SKILL.md` にあります。

## 使い方

1. 元資料（銀行・カードの明細CSV、請求書・領収書のPDFなど）を `accounting/inbox/` に置く
2. Claude Code で依頼する

```
/keiri 月次締め 2026-09
/keiri inbox の9月の明細を仕訳して
/keiri 〇〇社あてに9月分の取次手数料の請求書を作って
/keiri 今月の支払予定表を作って
```

個別の担当を直接呼ぶこともできます（例：「keiri-zeimu-review でこの仕訳下書きをチェックして」）。

3. 成果物は `accounting/output/` に出ます。内容を確認し、freee に登録します。

## ファイル構成

```
accounting/
├── rules/
│   ├── common.md       … 全員が守る共通ルール（★会社の前提を記入）
│   ├── kamoku.md       … 当社の勘定科目・税区分ルール（使うほど育てる）
│   └── tax-notes.md    … 税制メモ（経過措置の割合など、日付で変わるもの）
├── templates/
│   ├── getsuji-checklist.md … 月次締めチェックリスト
│   └── seikyusho.md         … 請求書のひな形
├── inbox/   … 元資料を置く（Git 管理外）
└── output/  … 成果物（Git 管理外）
```

## 最初にやること（初回のみ）

1. `rules/common.md` の ★ を記入する：決算月、消費税の方式（原則課税／簡易課税）、インボイス登録番号、税理士の有無
   - 法人の「2割特例」は 2026-09-30 を含む課税期間で終了しています。それ以後の方式を決めて記入してください
2. `rules/kamoku.md` の「★未決定」（SaaS を支払手数料／通信費のどちらにするか）を決める
3. （任意）freee と直接つなぐ：freee 公式の MCP サーバー（freee-mcp）を入れると、エージェントが freee の過去の取引・試算表を読めるようになります

```
/plugin marketplace add freee/freee-mcp
/plugin install freee-mcp@freee-mcp-marketplace
```

   freee-mcp は書き込み（登録・更新・削除）もできるため、エージェントには読み取りだけを許可しています（各定義ファイルに記載）。登録はユーザーの指示で行ってください。

## 注意

- 生データ（通帳・明細・請求書・給与）は `inbox/` 以外に置かないでください。`inbox/` と `output/` は `.gitignore` でコミット対象外です。
- AIの判定は下書きです。税務判断・申告は、最終的に顧問税理士に確認してください。
- 税制は毎年変わります。`rules/tax-notes.md` の最終確認日から1年たったら見直してください。
