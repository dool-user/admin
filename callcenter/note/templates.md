# templates.md（売れた記事の型）

売れた記事の構成だけを残す。売れるたびに 編集長が打合せの決定をもとに足す。

## 基本の型
1. タイトル：誰の・どんな悩みが・どうなるか（例：「営業を1人で回している人が、Claude で文面作りを10分にした手順」）
2. 冒頭3行：対象読者／この記事でできること／筆者が実際にやったこと
3. 無料部分：悩みの整理 → 結論の一部 → 有料部分に何があるか（目次）
4. `--- ここから有料 ---`
5. 有料部分：手順（番号付き）→ 実際に使ったファイル・文面 → つまずいた点と直し方 → チェックリスト
6. 最後：質問の受け方、次の記事の予告（決まっているときだけ）

## A03（MEO）の記事の締め（社長の指示・9/30）
「難しいと思った方はこちら」の案内を必ず入れる。
- 無料部分の最後（有料の区切りの直前）に1行：「自分でやるのは難しそう、と思った方へ：無料でご相談いただけます。▶ 無料相談フォーム（URL?src=記事ID）」
- 有料部分の最後に「『自分でやるのは難しい』と思ったら」の見出しと、約束3つ（相談は無料／無理な勧誘はしない／順位の保証はしない）とフォームへのリンク
- 筆者が MEO ツールを扱う会社にいることを、記事の前半で明記する
- フォーム：`../meo/index.html`（公開後の URL を入れる）

## 画像（9/30 社長の指示：類似記事にならって画像を入れる）
- 見出し画像（1920×1006・note の推奨 1280×670 と同じ比率）を全記事に付ける
- 本文には「この記事のポイント」図、「保存用チェックリスト」図、流れのある記事は図解を入れる
- 画像は `python tools/build_note_images.py <記事ID>` で作る。下書きに `![...](../images/<ID>/...png)` が差し込まれるので、note に貼るときは同じ位置に画像をアップロードする
- 図解を増やすときは `tools/build_note_images.py` の DIAGRAMS に足す
