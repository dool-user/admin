# note 事業部 毎日の進め方（PDCA）

毎日この順で回す。**PDCA は必ず1周させる。** 数字がない日も「測れていないこと」を Check に書いて1周させる。

| 時刻の目安 | 誰が | 何をする | 出すもの |
|---|---|---|---|
| 1 | リサーチ5人（並列・互いのメモを見ない） | それぞれの視点で調べる | `daily/<日付>/research/r1〜r5.md` |
| 2 | データサイエンティスト5人（並列・互いのメモを見ない） | リサーチ5本＋自社の数字＋前日の PDCA を読んで個人メモ | `daily/<日付>/ds/ds1〜ds5.md` |
| 3 | データサイエンティスト5人の打合せ | 司会が進め、決定と少数意見を残す | `daily/<日付>/meeting.md` |
| 4 | 編集長 | 打合せ報告をもとにライター・SNS への指示と今日の仮説を出す | `daily/<日付>/editor.md`・`pdca.csv` に追記 |
| 5 | ライター3人・SNS | 指示どおりに原稿・投稿案を作る | `out/drafts/`・`out/sns/` |
| 6 | センター長 | 社長への日報スライドを作る | `daily/<日付>/report.md`（スライドの元） |

## PDCA の対応
- **Plan**：編集長の `editor.md`（今日の仮説・施策・判定に使う数字・判定日）
- **Do**：ライター・SNS の制作、社長の公開・投稿
- **Check**：翌日のリサーチ（自社データ派）とデータサイエンティストが、判定日が来た仮説の結果を `pdca.csv` に入れる
- **Act**：翌日の打合せで「続ける／直す／やめる」を決める

## 考え方をそろえないためのルール
- リサーチもデータサイエンティストも、**自分のメモを出すまで他の人のメモを読まない**
- 打合せは「全員の意見 → 反論 → 決定 → 少数意見」の順。多数決にしない。決めるのはその日の司会
- 懐疑派（ツバサ）の反論には、必ず誰かが答える
- 5人が同じ結論になった日は、司会が「全員一致の理由」と「それでも外れるとしたら何が原因か」を書く

## 打合せの司会（日替わり）

|---|---|---|---|---|---|---|---|
| 司会 | アキラ（ベイズ） | ノゾミ（実験） | マコト（ファネル） | ツバサ（懐疑） | イオリ（経済性） | アキラ | ノゾミ |

## 日報スライド（社長へ）
`templates/report.md` の構成で `daily/<日付>/report.md` を作り、スライドにして社長に届ける。
1. 今日の結論（3行）
2. 数字：アカウント別の売上・目標100万円までの差・公開本数（まだ数字がないものは「未計測」）
3. PDCA：昨日の仮説 → 結果 → 判定
4. リサーチ5人の要点（1人1行）
5. 打合せで決まったこと・少数意見
6. 編集長の今日の指示
7. 社長にお願いしたいこと（公開・数字の提供・確認）
