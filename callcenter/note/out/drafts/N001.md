# Claude Code で17人の営業チームを組んだ手順と、実際のファイル一式

**こんな人向け：** 営業を少人数で回していて、リスト作り・文面作り・点検・事務に時間を取られている経営者や営業責任者。

**この記事でできること：** Claude Code の「サブエージェント」を使って、SV・アポインター・リスト担当・マーケ・事務がそろった営業チームを作れます。チームが毎回読むルールの書き方と、AI の失敗を減らしていく仕組みも入っています。

**筆者がやったこと：** 自社の営業のために、Claude だけで SV 2人・アポインター 10人・リスト抽出 1人・マーケ 1人・事務 3人のチームを組みました。【社長確認：始めた時期と、作るのにかかった時間】

---

## AI に営業を任せようとして、最初につまずいたこと

AI に「営業文を書いて」と頼むと、それらしい文章はすぐに出てきます。でも、実際に送れる文面はほとんどありませんでした。

- 店のことを調べずに、どの店にも同じことを書く
- 「必ず売上が上がります」のような、言ってはいけないことを言う
- 「営業お断り」と書いてあるフォームにも送ろうとする

原因は AI の性能ではありませんでした。**人間の新人に渡すような「ルール」と「点検」を渡していなかった**ことです。

## 結論：役割ごとに分けて、全員に同じ3つのファイルを読ませる

うまく回り始めたのは、次の3つをそろえてからです。

1. **役割を分ける**：1人の AI に全部やらせず、リスト担当・文面担当・点検担当を分ける
2. **毎回読むルールを短く書く**：`CLAUDE.md` に守ってほしいことだけを書く
3. **出す前に点検させる**：`review.md` に点検項目を書き、「出す前に全部確かめて、引っかかったら直して」と1行足す

この記事の有料部分では、実際に使っている組織図・ファイル8つの中身・エージェントの指示書を、そのまま載せています。

**無料部分のまとめ（ここだけでも使えます）**
- AI には「何をするか」より先に「何をしてはいけないか」を渡す
- 1人に全部やらせず、作る役と点検する役を分ける
- 直したことは AI 自身に記録させる（何を・なぜ・次からどうするかの3行）

### 有料部分の目次
1. 組織図：17人の役割と、仕事の流れ
2. 8つのファイルの中身（CLAUDE.md・review.md・mistakes.md ほか）
3. エージェントの指示書5つ（コピーして使える）
4. 「送信は人」にした理由と、送信の手前で止める補助ツール
5. つまずいたこと3つと、直し方
6. 明日から始めるチェックリスト

## 1. 組織図：17人の役割と、仕事の流れ

| 担当 | 人数 | やること |
|---|---|---|
| センター長 | 1（メインのセッション） | 仕事の割り振りと社長への報告 |
| SV | 2 | アポインター5人ずつの文面を点検し、承認か差し戻し |
| アポインター | 10 | 店ごとに問い合わせフォーム・DM の文面を作る |
| リスト抽出 | 1 | 送り先の店と、問い合わせフォーム・Instagram を探す |
| マーケ | 1 | 返信率の高い書き出しを分析し、ルールを育てる |
| 事務 | 3 | 返信への返事の案・日程調整・案件票 |

流れは次のとおりです。

1. リスト抽出が、送り先と連絡先を探す（「営業お断り」の店は外す）
2. アポインター10人が並列で、店ごとの文面を「下書き」にする
3. SV が点検して「承認」か「差し戻し」
4. **人が**承認済みの文面を確認して送る
5. 返信が来たら、事務が返事の案と日程調整を作る

ポイントは、**SV は5人に1人**にしたことです。点検の数が多すぎると、SV の点検が雑になりました。【社長確認：実際にそう感じた場面があれば1行】

## 2. 8つのファイルの中身

全員が読むファイルを、役割ごとに分けています。

```
CLAUDE.md      毎回読む約束ごと
character.md   人柄・口調
templates.md   返信が来た文面の型
hooks.md       効いた一言目
knowledge.md   商材の知識（数字は確認済みのものだけ）
ng-words.md    使わない言葉
review.md      出す前の点検
mistakes.md    直させたこと
```

### CLAUDE.md（実物から抜粋）
```
- 1回目の連絡で売り込まない。目的は「15分の説明の日程」だけ
- 数字は knowledge.md にある値だけ使う。書いていなければ「確認して折り返します」
- 出す前に review.md を全部確かめて、引っかかったら直す
- 作業の終わりに、直された点を mistakes.md に足す（何を・なぜ・次からどうするか の3行）
```

**短く書くのがコツです。** 毎回読まれるので、長いと守られない項目が出てきます。

### review.md（実物から抜粋）
```
- [ ] 送り先に「営業お断り」の表記がない
- [ ] 同じ店に、この30日で送っていない
- [ ] 名乗りと連絡先、「連絡が不要な場合の伝え方」がある
- [ ] ng-words.md の言葉を使っていない
- [ ] 1通目で申込を迫っていない
```

### mistakes.md の書き方
```
何を：フォームの下に「営業のご連絡はご遠慮ください」とあった店に下書きを作った
なぜ：フォームのページの下まで読まなかった
次から：review.md の1行目を、フォームのページ全体で確かめる
```
作業の終わりに「今回直させたところを mistakes.md に足して。何を・なぜ・次からどうするかの3行で」と送るだけです。**言い回しの直しは ng-words.md に移す**と、同じ言葉を二度と使わなくなります。

## 3. エージェントの指示書（コピーして使える）

Claude Code では `.claude/agents/<名前>.md` に指示書を置くと、その役割の AI を呼び出せます。以下は SV の例です。

```markdown
---
name: sv
description: スーパーバイザー。アポインター5人の下書きを review.md で点検して承認・差し戻しし、差し戻し理由を集計する。
tools: Read, Write, Edit, Glob, Grep
---
あなたは営業部の SV です。担当は自分のチームのアポインター5人だけ。

必ず最初に読む：CLAUDE.md review.md ng-words.md knowledge.md mistakes.md

1. 下書きを review.md で1件ずつ点検
   - 全部OK → 状態を「承認済」
   - ✗ がある → 「差し戻し」にし、どの項目かを書く
2. 差し戻しや同じ失敗は mistakes.md に3行で足す
3. 返信につながった文面は templates.md に足す提案を出す
```

【社長確認：アポインター・リスト抽出・マーケ・事務の指示書も同じ形で載せる（callcenter/.claude/agents/ の実物から、社名や連絡先を消して貼る）】

## 4. 「送信は人」にした理由

最初は送信まで自動にしようと考えました。やめた理由は3つです。

- Instagram は、公式の仕組みでは相手から先に連絡がないと DM を送れない。非公式の自動送信は規約違反になりうる
- 問い合わせフォームには「営業お断り」と書いてある店がある。送る前に人の目で見たい
- 送りすぎると迷惑行為と受け取られる。1日の上限を人が管理したい

そこで、**フォームに自動で入力して、送信ボタンの手前で止まる**補助ツールを作りました。人は内容を見て、送信ボタンを押すだけです。「営業お断り」の表記を見つけたフォームには入力しません。

## 5. つまずいたこと3つと、直し方

| つまずき | 原因 | 直し方 |
|---|---|---|
| どの店にも同じ文面になる | 店の情報を渡していなかった | リストに口コミ数・公式サイト・Instagram を入れ、「店について1つだけ具体的に書く。調べていないことは書かない」と character.md に書いた |
| 言ってはいけない表現が出る | 禁止事項を書いていなかった | ng-words.md に「使わない → 代わりに」の表で書いた |
| 【社長確認：3つ目の実体験】 | | |
