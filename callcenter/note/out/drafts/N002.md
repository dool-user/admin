# CLAUDE.md と review.md だけで始める、失敗しない AI への仕事の渡し方

**こんな人向け：** AI を仕事に使い始めたけれど、出てきた文章を毎回自分で直している人。エンジニアでなくても読めるように書きました。

**この記事でできること：** ファイル2つと1行の指示だけで、AI に「守ってほしいこと」と「出す前の点検」を渡せるようになります。営業文・記事・資料の3つの例と、コピーして使える型が入っています。

**筆者がやったこと：** 自社の営業チームと note の編集チームを、Claude Code（AI に作業をさせる道具）で動かしています。どのチームも、この記事の2つのファイルを土台にしています。【社長確認：この形で運用を始めた時期（書けなければこの一文を消す）】

**この記事について：** 2026年9月に書きました。Claude Code の機能名・画面は変わりやすいので、使う前に公式の最新情報を確認してください。

## AI に仕事を頼むと、よく起きること

AI に「営業文を書いて」「記事を書いて」と頼むと、それらしい文章はすぐに出てきます。でも、そのまま使えるとは限りません。

- 言ってはいけないこと（「必ず儲かる」など）を書く
- 確かめていない数字を、それらしく埋める
- 前に直したことを、次の回でまた間違える

これは AI が悪いというより、**新人に渡すような「約束ごと」と「点検表」を渡していない**ことが多いです。人間の新人にも、口で1回言っただけでは伝わりません。

## 結論：ファイル2つと、1行の指示

始めるのに必要なのは、これだけです。

1. **CLAUDE.md**：毎回守ってほしい約束ごと。短く書く
2. **review.md**：出す前の点検表。「はい／いいえ」で答えられる形にする
3. **1行の指示**：「出す前に review.md を全部確かめて、引っかかったら直す」

Claude Code は、作業フォルダに置いた `CLAUDE.md` を、セッション（作業のひと区切り）を始めるたびに読みます。だから、毎回同じ説明をしなくて済みます。

**無料部分のまとめ（ここだけでも使えます）**
- AI には「何をするか」より先に「何をしてはいけないか」を渡す
- 約束ごとは短く書く。長いと、守られない項目が出てくる
- 点検表は「はい／いいえ」で答えられる文にする
- 「出す前に点検して、引っかかったら直す」を1行で頼む

### 有料部分の目次
1. 準備するもの（フォルダとファイル2つ）
2. CLAUDE.md の書き方と、実物
3. review.md の書き方と、実物

## 1. 準備するもの

仕事ごとにフォルダを1つ作り、ファイルを2つ置きます。

```
仕事のフォルダ/
  CLAUDE.md    毎回守る約束ごと
  review.md    出す前の点検表
```

ファイルはメモ帳で作れます。`.md` は「マークダウン」という、ただの文字のファイルです。

Claude Code 以外のチャット型の AI でも、考え方は同じです。会話の最初に2つの中身を貼り付けてから頼みます。

## 2. CLAUDE.md の書き方

書くのは3種類だけです。

- **目的**：この仕事で何をしたいか（1行）
- **してはいけないこと**：言ってはいけないこと・書いてはいけないこと
- **出す前の約束**：review.md で点検すること

### 実物（このチームの CLAUDE.md から抜粋）
```
- 数字・実績は knowledge.md と社長が確認した事実だけ。ないものは書かない（作らない）
- 出す前に その部の review.md を全部確かめて、引っかかったら直す
- 送信・投稿・公開は人が行う。Claude は DM やフォームを送らず、note やSNSに投稿しない
```

3行目は大事です。**最後に外へ出すのは人**、と決めておきます。AI が間違えても、外に出る前に止められます。

### コピー用の型
```
# CLAUDE.md
この仕事の目的：〇〇（1行）

## 守ること
- 数字は、私が渡した資料にあるものだけ使う。なければ「確認が必要」と書いて空ける
- 〇〇とは書かない（言ってはいけないこと）
- 出す前に review.md を全部確かめて、引っかかったら直す
- 送る・公開するのは私。AI は下書きまで
```

**5行以内が目安です。** 毎回読まれるので、長いほど1つずつが薄まります。細かいルールは review.md に回します。

## 3. review.md の書き方

点検表のコツは1つです。**「はい／いいえ」で答えられる文にする。**

- ✗「わかりやすく書く」（何をもって、わかりやすいのか決められない）
- ○「1文が60文字以内」「専門用語に一言の説明がある」

### 実物（note の記事用 review.md から抜粋）
```
- [ ] 実績・数字はすべて knowledge.md にあるか、社長が確認したもの
- [ ] 無料部分だけでも読者に役立つことが1つある
- [ ] ng-words.md の言葉・誇大な表現がない
- [ ] 他人の文章・画像をそのまま使っていない。引用には出典がある
- [ ] 個人情報・取引先名・APIキーなどが入っていない
```

冒頭には「1つでも ✗ なら直してから出す」と書いています。点検して終わりではなく、**直すところまで**が仕事だと伝えるためです。

### コピー用の型
```
# review.md（出す前の点検）
1つでも ✗ なら直してから出す。

- [ ] 数字は、渡した資料にあるものだけ
- [ ] 相手の名前・日付・金額が正しい
- [ ] 言ってはいけない言葉がない
- [ ] 個人情報・社外秘が入っていない
- [ ] 〇〇（この仕事だけの点検）
```

最初は5項目で十分です。増やすのは、実際に引っかかったことが出てからにします。

## 4. 1行の指示をどこに書くか

「出す前に review.md を全部確かめて、引っかかったら直す」。この1行は、2か所に書きます。

1. **CLAUDE.md の中**：毎回読まれるので、忘れられにくい
2. **役割ごとの指示書の最後**：作業の最後に目に入る

Claude Code では、`.claude/agents/` に役割ごとの指示書を置けます（サブエージェントと呼びます）。このチームのアポインター（営業文を作る役）の指示書は、最後がこの1行です。

```
6. 出す前に review.md を全部確かめる
```

note のライターの指示書も同じです。

```
4. 出す前に review.md を全部確かめ、状態=校正待ち
```

指示書を作らない場合は、頼むたびに最後にこの1行を足すだけでも効きます。

## 5. 非エンジニア向けの例

### 例1：営業文（問い合わせフォーム・DM）

このチームの営業文の点検表から、そのまま使える項目です。

```
- [ ] 送り先に「営業お断り」などの表記がない
- [ ] 名乗り（会社名・名前）と、連絡先・署名がある
- [ ] 連絡が不要な場合の伝え方が書いてある
- [ ] 1通目で申込を迫っていない
- [ ] Instagram DM は5行以内、URLを貼っていない
```

CLAUDE.md には「1回目の連絡の目的は、15分の説明の日程だけ」のように、**ゴールを1つだけ**書きます。

### 例2：記事・ブログ

```
# CLAUDE.md
- 私の一人称で書く。やっていないことは書かない
- 1文を短く。1段落3行まで
- 出す前に review.md を全部確かめて、引っかかったら直す

# review.md
- [ ] 数字・実績は、私が確認したものだけ
- [ ] 他人の文章をそのまま使っていない。引用には出典がある
- [ ] 専門用語に、最初に一言の説明がある
```

### 例3：社内資料・提案書

```
# CLAUDE.md
- 読む人：〇〇部の部長。1枚目で結論を言う
- 数字は添付の表にあるものだけ。計算したときは式も書く
- 出す前に review.md を全部確かめて、引っかかったら直す

# review.md
- [ ] 1枚目に結論と、お願いしたいことがある
- [ ] 数字が添付の表と一致している
- [ ] 日付・社名・金額の書き間違いがない
- [ ] 社外に出してはいけない情報が入っていない
```

どの例も、**「数字は渡したものだけ」**が入っています。AI がやりがちなことの1つが、それらしい数字で空白を埋めることだからです。

## 6. そのまま使える頼み方の文例

```
CLAUDE.md を読んでから、〇〇の下書きを作って。
出す前に review.md を全部確かめて、引っかかったら直す。
直したところがあれば、最後に箇条書きで教えて。
```

最後の1行を足すと、AI が何を点検して直したのかが見えます。あなたが見る場所が絞れます。

## 7. つまずきやすい点と、直し方

| つまずき | 原因 | 直し方 |
|---|---|---|
| CLAUDE.md を書いたのに守られない | 長すぎる・あいまい | 5行以内にし、細かい話は review.md に移す |
| 点検したと言うのに、直っていない | 「確かめて」だけで「直す」を頼んでいない | 「引っかかったら直す」まで1行に入れる |
| 点検表がどんどん長くなる | 思いつきで項目を足している | 足すのは、実際に引っかかったことだけ |
| 数字が勝手に埋まる | 「ないときどうするか」を書いていない | 「なければ『確認が必要』と書いて空ける」と書く |

点検表は、使いながら育てるものです。このチームの営業文の review.md にも、あとから「嫌われない営業の点検（案）」として4項目が足されています。足すかどうかは、点検役（SV）が決める形にしています。

## 8. 明日から始めるチェックリスト

- [ ] 仕事のフォルダを1つ作る
- [ ] CLAUDE.md に、目的とやってはいけないことを5行以内で書く
- [ ] review.md に「はい／いいえ」で答えられる点検項目を5つ書く
- [ ] 頼むときに「出す前に review.md を全部確かめて、引っかかったら直す」を足す
- [ ] 送る・公開するのは自分、と決める

直させたことを次に活かす方法（mistakes.md）は、別の記事で書く予定です。
