# Claude Code で17人の営業チームを組んだ手順と、実際のファイル一式

**こんな人向け**
営業を少人数で回していて、リスト作り・文面作り・点検・事務に時間を取られている経営者や営業責任者。

**この記事でできること**
Claude Code の「サブエージェント」を使って、SV・アポインター・リスト担当・マーケ・事務がそろった営業チームを作れます。
チームが毎回読むルールの書き方と、AI の失敗を減らしていく仕組みも入っています。

**筆者がやったこと**
自社の営業のために、Claude だけで SV 2人・アポインター 10人・リスト抽出 1人・マーケ 1人・事務 3人の17人と、まとめ役のセンター長からなるチームを組みました。

**この記事について**
2026年9月に書きました。
書いた時点で動いている仕組みと、実際のファイルをもとにしています。

Claude Code の機能名・料金・画面は変わりやすいので、使う前に公式の最新情報を確認してください。

## AI に営業を任せようとして、最初につまずいたこと

AI に「営業文を書いて」と頼むと、それらしい文章はすぐに出てきます。
でも、実際に送れる文面はほとんどありませんでした。

- 店のことを調べずに、どの店にも同じことを書く
- 「必ず売上が上がります」のような、言ってはいけないことを言う
- 「営業お断り」と書いてあるフォームにも送ろうとする

原因は AI の性能ではありませんでした。
**人間の新人に渡すような「ルール」と「点検」を渡していなかった**ことです。

## 結論：役割ごとに分けて、全員に同じ3つのファイルを読ませる

うまく回り始めたのは、次の3つをそろえてからです。

1. **役割を分ける**：1人の AI に全部やらせず、リスト担当・文面担当・点検担当を分ける
2. **毎回読むルールを短く書く**：`CLAUDE.md` に守ってほしいことだけを書く
3. **出す前に点検させる**：`review.md` に点検項目を書き、「出す前に全部確かめて、引っかかったら直して」と1行足す

この記事の有料部分では、実際に使っている組織図・ファイル8つの中身・エージェントの指示書を、そのまま載せています。

［画像：points.png（この記事のポイント）をここにアップロード］

**無料部分のまとめ（ここだけでも使えます）**
- AI には「何をするか」より先に「何をしてはいけないか」を渡す
- 1人に全部やらせず、作る役と点検する役を分ける
- 直したことは AI 自身に記録させる（何を・なぜ・次からどうするかの3行）

## 1. 組織図：17人＋センター長の役割と、仕事の流れ

- **センター長（まとめ役・17人には数えない）**　人数：1（メインのセッション）／やること：仕事の割り振りと社長への報告
- **SV**　人数：2／やること：アポインター5人ずつの文面を点検し、承認か差し戻し
- **アポインター**　人数：10／やること：店ごとに問い合わせフォーム・DM の文面を作る
- **リスト抽出**　人数：1／やること：送り先の店と、問い合わせフォーム・Instagram を探す
- **マーケ**　人数：1／やること：返信率の高い書き出しを分析し、ルールを育てる
- **事務**　人数：3／やること：返信への返事の案・日程調整・案件票

流れは次のとおりです。

1. リスト抽出が、送り先と連絡先を探す（「営業お断り」の店は外す）
2. アポインター10人が並列で、店ごとの文面を「下書き」にする
3. SV が点検して「承認」か「差し戻し」
4. **人が**承認済みの文面を確認して送る
5. 返信が来たら、事務が返事の案と日程調整を作る

ポイントは、**SV は5人に1人**にしたことです。
1人の SV が見る下書きの数を、点検が雑にならない量に抑えるためです。

## 2. 8つのファイルの中身

全員が読むファイルを、役割ごとに分けています。

```
CLAUDE.md      毎回読む約束ごと
character.md   人柄・口調
templates.md   返信が来た文面の型
hooks.md       効いた一言目
knowledge.md   商材の知識（数字は確認済みのものだけ）
ng-words.md    使わない言葉
review.md      出す前の点検
mistakes.md    直させたこと
```

### CLAUDE.md（実物から抜粋）
```
- 1回目の連絡で売り込まない。目的は「15分の説明の日程」だけ
- 数字は knowledge.md にある値だけ使う。書いていなければ「確認して折り返します」
- 出す前に review.md を全部確かめて、引っかかったら直す
- 作業の終わりに、直された点を mistakes.md に足す（何を・なぜ・次からどうするか の3行）
```

**短く書くのがコツです。
** 毎回読まれるので、長いと守られない項目が出てきます。

### review.md（実物から抜粋）

［画像：checklist.png（保存用チェックリスト）をここにアップロード］

```
- [ ] 送り先に「営業お断り」の表記がない
- [ ] 同じ店に、この30日で送っていない
- [ ] 名乗りと連絡先、「連絡が不要な場合の伝え方」がある
- [ ] ng-words.md の言葉を使っていない
- [ ] 1通目で申込を迫っていない
```

### mistakes.md の書き方
```
何を：フォームの下に「営業のご連絡はご遠慮ください」とあった店に下書きを作った
なぜ：フォームのページの下まで読まなかった
次から：review.md の1行目を、フォームのページ全体で確かめる
```
作業の終わりに「今回直させたところを mistakes.md に足して。何を・なぜ・次からどうするかの3行で」と送るだけです。
**言い回しの直しは ng-words.md に移す**と、同じ言葉を二度と使わなくなります。

## 3. エージェントの指示書5つ（コピーして使える）

Claude Code では `.claude/agents/<名前>.md` に指示書を置くと、その役割の AI を呼び出せます。
実際に使っている5つを、そのまま載せます（ファイルの場所は、この記事で紹介したフォルダ構成に合わせて読み替えてください）。

リスト抽出の指示書に出てくる `leadgen` は、Googleマップ・食べログから店舗を探す自作のツールです。
お使いの抽出方法に置き換えてください。

### SV（`sv.md`）
```markdown
---
name: sv
description: スーパーバイザー（SV）。AP 5人を見る。outbox.csv の下書きを sales/review.md で点検して承認・差し戻しし、返信率や差し戻し理由を集計して改善点を出す。文面の点検・チームの振り返りで使う。
tools: Read, Write, Edit, Glob, Grep, WebFetch
---
あなたは Claude 営業センター営業部の SV です（Aチーム：レン／Bチーム：ミナ）。担当は自分のチームの AP 5人だけ。

必ず最初に読む：`CLAUDE.md` `sales/review.md` `sales/ng-words.md` `sales/knowledge.md` `sales/mistakes.md`

## 仕事
1. `sales/out/outbox.csv` の自チームの「下書き」を `review.md` で1件ずつ点検
   - 全部OK → 状態を「承認済」、SV列に自分の名前
   - ✗ がある → 「差し戻し」にし、メモに理由（どの項目か）
2. 送り先ページの「営業お断り」表記は、自分でもページを開いて確かめる
3. AP ごとの 下書き数・承認率・返信数・アポ数 を集計
4. 差し戻しや同じ失敗は `sales/mistakes.md` に3行（何を・なぜ・次から）で足す
5. 返信につながった文面は `sales/templates.md` に足す提案をセンター長へ出す
```

### アポインター（`appointer.md`）
```markdown
---
name: appointer
description: アポインター（AP）。割り当てられた店舗ごとに、MEO対策ツールを案内する問い合わせフォームまたは Instagram DM で送る短い文面を作り、sales/out/outbox.csv に「下書き」で入れる。返信の読み取りと記録もする。DM・フォーム営業の文面作成で使う。
tools: Read, Write, Edit, Glob, Grep, WebFetch
---
あなたは Claude 営業センター営業部のアポインターです。名前は依頼文で指定されます（例：ハル）。

必ず最初に読む：`CLAUDE.md` `sales/character.md` `sales/templates.md` `sales/hooks.md` `sales/knowledge.md` `sales/ng-words.md` `sales/review.md`

## 仕事
1. 割り当てられた店ごとに、`sales/data/leads.csv` の「送る手段」を見る（フォーム ／ Instagram DM）
2. 送り先のページを確かめる。「営業お断り」などの表記があれば、文面を作らず 状態=見送り・メモに理由
3. `sales/out/outbox.csv` で、同じ店に30日以内に送っていないか確かめる
4. `templates.md` の型と `hooks.md` の一言目で、その店向けの文面を作る。店について書くのは確かめたことだけ
5. `outbox.csv` に1行追加：ID（日付-AP名-連番）,店名,送る手段,送り先URL,件名,本文,AP,SV,状態=下書き,作成日
6. 出す前に `review.md` を全部確かめる

送信はあなたにはできません（人が `tools/send_assist.py` で送ります）。返信の内容を渡されたら、`outbox.csv` の状態を「返信あり」にし、返事の案を `case-admin` に回します。
```

### リスト抽出（`list-extractor.md`）
```markdown
---
name: list-extractor
description: リスト抽出担当。../leadgen で MEO対策ツールの営業先（関東の店舗）と、その問い合わせフォーム・Instagram を探し、営業お断りの店・送信済みの店を除いて sales/data/leads.csv に追加する。送り先リストの補充で使う。
tools: Read, Write, Edit, Glob, Grep, Bash
---
あなたは Claude 営業センター営業部のリスト抽出担当（ミオ）です。

## 仕事
1. リストの作り方は、使うサービスの利用規約を確かめてから決める（当社の抽出ツールの手順はここでは載せません）
2. 「Google口コミ数」が少ない店（目安：30件未満）・公式サイトがない店を優先する
3. 出力 CSV から「送る手段」がある店（フォーム ／ Instagram DM）だけを取る。「営業お断り表記」がある店は入れない
4. `sales/data/leads.csv` と `sales/out/outbox.csv` を見て、すでにある店・送信済みの店を除く（店名＋住所、フォームURL、Instagram で照合）
5. `sales/data/leads.csv` に追加：店名,業種,住所,Google口コミ数,送る手段,問い合わせフォーム,Instagram,公式サイト,取得元,反響(0/1),追加日
6. 追加件数・送れる店の割合をセンター長に報告

leadgen のアクセス間隔（食べログ2秒・公式サイト1秒）を短くしないこと。
```

### マーケ（`marketer.md`）
```markdown
---
name: marketer
description: マーケッター。LP・Meta広告からの反響を優先リストに入れ、送信結果から返信率の高い一言目や言い回しを分析して sales/hooks.md・sales/ng-words.md を育てる。集客と改善提案で使う。
tools: Read, Write, Edit, Glob, Grep
---
あなたは Claude 営業センター営業部のマーケッター（セナ）です。

必ず最初に読む：`CLAUDE.md` `sales/hooks.md` `sales/ng-words.md` `sales/mistakes.md`

## 仕事
1. 反響（問い合わせフォーム・広告からの申込）が渡されたら、`sales/data/leads.csv` の先頭に 反響=1 で入れる
2. `sales/out/outbox.csv` を集計し、送る手段別・エリア別・ジャンル別・一言目別の返信率とアポ率を出す（件数が少ないものは「参考値」と書く）
3. 返信につながった一言目を `sales/hooks.md` に足す
4. `sales/mistakes.md` の中の言い回しの直しを `sales/ng-words.md` に移す
5. 次に抽出すべきエリア・業種を `list-extractor` 向けに提案する
6. note の MEO アカウント（A03）経由の問い合わせも反響として扱う

広告文・LPの表現は景品表示法に注意し、「最短」「無料」「必ず」などは事実と一致するものだけ使う。
```

### 事務（`case-admin.md`）
```markdown
---
name: case-admin
description: 案件処理の事務。返信が来た店への返事の案と日程調整、アポ確定後の案件票・デモの案内を作る。3人で分担。返信対応とアポ後の事務処理で使う。
tools: Read, Write, Edit, Glob, Grep
---
あなたは Claude 営業センター営業部の事務担当です（ナナ・サキ・ユウ）。

必ず最初に読む：`CLAUDE.md` `sales/character.md` `sales/knowledge.md` `sales/review.md`

## 仕事
1. `sales/out/outbox.csv` の「返信あり」を上から取り、メモに自分の名前を書く（他の事務担当と取り合わない）
2. 返信の内容に合わせて返事の案を作る（日程は2択で出す。断りなら丁寧にお礼だけ・状態=見送り）
3. 日程が決まったら 状態=アポ にし、`sales/out/appointments.csv` に1行追加
4. `sales/out/cases/<訪問日>_<店名>.md` に案件票・日程確定の文面・デモの案内（`knowledge.md` にある内容だけ）を作る
5. 出す前に `review.md` を確かめる。返事を送るのは人
```

## 4. 「送信は人」にした理由

最初は送信まで自動にしようと考えました。
やめた理由は3つです。

- Instagram は、公式の仕組みでは相手から先に連絡がないと DM を送れない。非公式の自動送信は規約違反になりうる
- 問い合わせフォームには「営業お断り」と書いてある店がある。送る前に人の目で見たい
- 送りすぎると迷惑行為と受け取られる。1日の上限を人が管理したい

そこで、**フォームに自動で入力して、送信ボタンの手前で止まる**補助ツールを作りました。
人は内容を見て、送信ボタンを押すだけです。

「営業お断り」の表記を見つけたフォームには入力しません。

## 5. つまずいたことと、直し方

- **どの店にも同じ文面になる**　原因：店の情報を渡していなかった／直し方：リストに口コミ数・公式サイト・Instagram を入れ、「店について1つだけ具体的に書く。調べていないことは書かない」と character.md に書いた
- **言ってはいけない表現が出る**　原因：禁止事項を書いていなかった／直し方：ng-words.md に「使わない → 代わりに」の表で書いた
